# Novedas - 2026-08-14

## Reestructuración de layout: calendario al inicio, aside sticky y info secundaria

Se reestructuró la página principal (`index.astro`) para dar prioridad al calendario y al detalle del día, moviendo la información secundaria debajo.

### Cambios de layout

1. **Hero compacto** (`#today`): se reemplazó el hero anterior (con bento grid de 4 tarjetas) por un hero compacto con kicker, título, subtítulo y meta-bar de pills. Se eliminó la tarjeta "Jornada seleccionada" del hero porque duplicaba la información del aside.
2. **Calendario + aside** (`#calendar`): subidos justo después del hero. El calendario mensual ocupa la columna principal y el detalle del día se muestra como `aside` con `position: sticky; top: 88px` en desktop para acompanar el scroll. En móvil (<960px) el aside vuelve a `position: static`.
3. **Info secundaria** (`#info`): las tarjetas "Que resuelve este MVP", "Fuente de verdad" y "Estado del dataset" se movieron a una sección de grid de 3 columnas debajo del calendario y el aside.
4. **Header**: los botones "Ingresar" y "Crear Cuenta" se ocultan vía `hideAuth={true}` en `PortalHeader`. Los nav links se actualizaron a `#today`, `#info`, `#ecosystem` y `#api`.

### Mejoras visuales

- Hero con halo gradiente del ecosistema (tokens `--color-brand-*`).
- Cards de lectura con hover suave (`border-color` + `box-shadow`).
- Grid de info secundaria responsive (3 cols → 1 col en <960px).
- Limpieza de CSS no usado (`.calendar-callout`, `.calendar-fact`, `.calendar-hero-grid` de la app).
- El CSS local (`calendario.css`) se reescribio por completo para el nuevo layout, manteniendo tokens del ecosistema.

### Archivos modificados

- `src/apps/calendario/src/pages/index.astro` — reestructuración completa del layout.
- `src/apps/calendario/src/styles/calendario.css` — CSS reescrito para el nuevo layout.
- `src/apps/calendario/src/components/SiteHeader.astro` — nav links actualizados y `hideAuth={true}`.

### Validaciones ejecutadas

- `pnpm --filter calendario check-types` (`astro check`): 0 errores, 0 warnings, 0 hints.
- Build: el error EPERM de symlink del adapter Vercel en Windows es preexistente y no está relacionado con loss cambios.
