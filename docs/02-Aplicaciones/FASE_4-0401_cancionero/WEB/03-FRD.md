## 3. Reglas de negocio

| ID                     | Regla                                                                                                                                                                                                                                                                                                                                                |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RB-0401-CANCIONERO-001 | Una canción debe tener al menos un tiempo litúrgico y un momento de misa asociado para ser publicada                                                                                                                                                                                                                                                 |
| RB-0401-CANCIONERO-002 | Solo el administrador puede cambiar el estado de una canción de "pendiente" a "publicado" o "rechazado"                                                                                                                                                                                                                                              |
| RB-0401-CANCIONERO-003 | Un músico no puede ver sus propias contribuciones como públicas hasta que el administrador las apruebe                                                                                                                                                                                                                                               |
| RB-0401-CANCIONERO-004 | La contribución se crea sin etiquetas litúrgicas finales; tiempo+momento se asignan en moderación por el rol `sacerdote` (o `admin`) antes de publicar                                                                                                                                                                                               |
| RB-0401-CANCIONERO-005 | El sistema debe registrar en auditoría quién contribuyó, quién aprobó y qué cambios se hicieron sobre las etiquetas originales                                                                                                                                                                                                                       |
| RB-0401-CANCIONERO-006 | El Motor A tokeniza la query por espacios y devuelve canciones donde al menos un token aparece en el titulo o en la letra, con matching OR y normalización sin acentos. Si la query esta vacia o no se informa, el filtro no se aplica y se devuelven todas las canciones publicadas                                                                 |
| RB-0401-CANCIONERO-007 | El Motor B aplica el filtro de tiempo liturgico cuando este viene informado; el momento es opcional y, si se informa, debe pertenecer a la lista de momentos del tiempo elegido. Si el tiempo no se informa, el filtro no se aplica y se devuelven todas las canciones publicadas                                                                    |
| RB-0401-CANCIONERO-008 | El Motor C es independiente del tiempo liturgico: cuando viene un momento, devuelve canciones con ese momento en cualquier tiempo, ignorando cualquier tiempo que venga informado. Si el momento no se informa, el filtro no se aplica y se devuelven todas las canciones publicadas                                                                 |
| RB-0401-CANCIONERO-009 | El esqueleto de 3 motores se presenta en una sola página `/buscar` con pestañas accesibles (roles ARIA `tablist`/`tab`/`tabpanel`); el motor activo persiste en query string                                                                                                                                                                         |
| RB-0401-CANCIONERO-010 | Sin filtros aplicados, el sistema muestra todas las canciones con `estado = publicado`, ordenadas por titulo. El encabezado del panel indica "N canciones aprobadas" en este caso; cuando hay al menos un filtro aplicado, dice "N canciones encontradas"                                                                                            |
| RB-0401-CANCIONERO-011 | La jerarquía de roles que Cancionero aplica a los slugs del ecosistema es: `admin` → "admin"; `sacerdote` → "sacerdote"; `coordinador` → "coordinador"; `musico` → "musico"; `usuario` (rol base) o sesión ausente → "invitado"                                                                                                                      |
| RB-0401-CANCIONERO-012 | En Cancionero pueden **contribuir** canciones los roles `coordinador`, `sacerdote` y `admin`. El rol `musico` aporta con listas de reproducción (no contribuye canciones). `invitado` y `usuario` no pueden contribuir. En la contribución no se define tiempo/momento final; puede incluir observaciones para moderación                            |
| RB-0401-CANCIONERO-013 | En Cancionero pueden **moderar** los roles `sacerdote` (evaluar y aprobar canciones) y `admin` (gestión completa). Cualquier otro rol (`musico`, `coordinador`, `invitado`) es redirigido a `/` al acceder a `/moderacion` o recibe 401/403 en los endpoints de moderación                                                                           |
| RB-0401-CANCIONERO-014 | Al registrarse desde Cancionero, el nuevo usuario recibe simultáneamente los roles `usuario` (id=4, asignado por el trigger `internal.handle_new_user`) y `musico` (id=5, asignado por el endpoint). El header `PortalHeader` muestra el nombre del perfil y un enlace a `/perfil`; el botón "Cerrar sesión" invalida la sesión y limpia las cookies |
| RB-0401-CANCIONERO-015 | Las páginas `/contribuir` y `/moderacion` validan la sesión y la capacidad en SSR (no en cliente). Si falta sesión, redirigen a `/auth/login?next=<ruta>`. Si la sesión existe pero la capacidad no, redirigen a `/` con un mensaje informativo                                                                                                      |

## 4. Validaciónes y errores esperados

| Contexto                              | Validación                                                                  | Error                                                                             |
| ------------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Contribución - título                 | Requerido, máximo 200 caracteres                                            | "El título de la canción es obligatorio"                                          |
| Contribución - letra                  | Requerido, texto limpio multilinea                                          | "La letra de la canción es obligatoria"                                           |
| Contribución - acordes                | Opcionales; cada uno con linea>=0, posicion>=0 y nombre 1-12 chars          | "El nombre del acorde no puede estar vacío" / "Posición inválida"                 |
| Contribución - observaciones          | Opcional, máximo 1000 caracteres                                            | "Las observaciones no pueden superar los 1000 caracteres"                         |
| Moderación - aprobación con etiquetas | Al aprobar, debe informar al menos un tiempo litúrgico y un momento de misa | "Debe seleccionar al menos un tiempo litúrgico y un momento de misa para aprobar" |
| Moderación - aprobación               | El recurso debe estar en estado "pendiente"                                 | "El recurso ya fue moderado anteriormente"                                        |
| Búsqueda - query libre                | Si se informa `q`, mínimo 2 caracteres                                      | "Ingrese al menos 2 caracteres para buscar"                                       |
| Búsqueda - Motor B                    | Si se informa `momento`, debe pertenecer a la lista del tiempo              | "El momento no pertenece al tiempo litúrgico seleccionado"                        |
| Búsqueda - params vacíos              | Ausencia de `q`/`tiempo`/`momento` permitida; devuelve catálogo             | No se genera error; se devuelven todas las canciones publicadas                   |

## 5. Estados funcionales

- **Estado `loading`:** Esqueleto de lista de resultados mientras se ejecuta la búsqueda; indicador de carga en panel de moderación al procesar una decisión.
- **Estado `empty`:** Mensaje "No se encontraron canciones" con sugerencia de ajustar filtros; en contribuciones vacías: "Aún no hay canciones para este tiempo litúrgico. ¡Sé el primero en contribuir!"
- **Estado `error`:** Notificación de error con mensaje específico y acción de reintento cuando la API de Calendario Litúrgico no responde o hay un error de red.
- **Estado `success`:** Confirmación visual tras contribuir exitosamente ("Tu canción fue enviada para moderación"); confirmación tras aprobar/rechazar en panel de moderación.
